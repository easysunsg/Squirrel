# Squirrel (松鼠库存管家) — 项目设计方案

> **项目寄语**：像松鼠一样精于囤积，但再也不会忘记你的“坚果”藏在哪里。

## 📌 项目概述

### 核心痛点

- **记不住买了啥**：批量采购后，过几天就忘得一清二楚。
- **记不住放哪了**：囤货时随手一塞，用的时候翻箱倒柜。
- **记不住保质期**：食材放烂、药品过期，造成极大的浪费。
- **想不起来要用**：空有满屋物资，每天开电视/做饭时依然执着于点外卖。

### 设计核心

围绕 **「主动提醒、一眼看懂、极简不费脑」** 设计，全面贴合懒人、健忘人群及 NAS/私有云爱好者的使用习惯。**拒绝死板的人工表单录入，全面由 AI 驱动。**

## 🛠️ 技术架构 (Architecture)

为了满足**本地部署、轻量无感、数据透明（Markdown化）**的需求，技术栈设计如下：

### 1. 后端与 AI 存储

- **后端核心**：FastAPI (Python)。提供高效的异步 API，方便集成大模型 SDK。
- **关系型数据库 (RDB)**：SQLite。
  - *双轨制设计*：数据主体存放在 SQLite 中以确保高性能的条件检索（如查询“3天内过期的生鲜”）。
  - *Markdown 自动同步*：每当库存发生增删改，系统自动在本地挂载目录生成/更新一份 inventory.md。用户无需打开网页，单看 Markdown 文件即可“一眼看懂”所有库存。
- **向量数据库 (Vector DB)**：Chroma。
  - 嵌入式设计，无需独立运行容器，内存占用极小。用于处理模糊语义搜索（如输入“洗澡用的”，自动匹配到“沐浴露”）。

### 2. 前端与多模态 (Web)

- **前端框架**：Next.js (React) + Tailwind CSS + Shadcn UI。
- **语音处理**：Web Audio API 采集音频，支持对接用户配置的在线 STT (Speech-to-Text) API，或可选本地轻量化 Whisper.bin。

### 3. 技术栈总览表

| 模块 | 推荐技术 | 理由 |
| --- | --- | --- |
| **Backend** | FastAPI | 优秀的异步性能，生态丰富，易于对接 AI 接口 |
| **RDB** | SQLite | 零配置，单文件，完美契合 Docker 本地数据挂载 |
| **Vector DB** | Chroma | 轻量级嵌入式向量库，无缝支持模糊语义搜索 |
| **Frontend** | Next.js | 响应式设计，极简风 UI，对 Docker 镜像打包友好 |
| **Data Export** | Auto-Markdown | 满足数据本地化、可读、易迁移的执念 |

## 🤖 AI 服务层 (Service)

### 1. 核心对话能力（语音/文字双支持）

无需死板的特定指令，完全支持自然口语对话：

- **新增物品**
  - *单件录入*：“我今天买了一把油麦菜，放冰箱下层。” -> AI 自动识别 物品名: 油麦菜、位置: 冰箱下层，并智能匹配生鲜类的默认保质期（如 3-5 天），录入成功后给予即时语音/文字反馈。
  - *批量拆分*：“买了鸡蛋、香蕉、猪肉，都放冰箱。” -> AI 自动拆分为三条记录分别录入。
- **减少/移除物品**
  - *口语消耗*：“刚才把青菜吃完了”、“橘子坏了，扔掉”、“拿了一瓶沐浴露用了”。 -> AI 自动标记为「已使用/已丢弃」，移出预警列表，更新库存。
- **修改信息**
  - *快速修正*：“把牛奶换到冰箱上层”、“土豆保质期再延 2 天”。

### 2. 智能查询与预警

- **全局模糊查询**：“我家里还有什么蔬菜？”、“我的感冒药放在哪了？”（通过向量数据库实现语义匹配）。
- **过期提醒问询**：“现在有哪些东西快要坏了？” -> AI 按紧急程度由高到低罗列，附带存放位置与剩余时长。
- **闲置查询**：“家里什么东西放了很久没动过？” -> 捞出长期未消耗的物资。

### 3. 专属增值能力

- **保鲜与消纳建议**：识别到临期食材时主动出谋划策。例如：“生菜还有 1 天到期，建议今晚清炒；剩余部分可焯水冷藏，延长 1 天寿命。”
- **防重复囤货提醒**：录入新物品时，若发现库存已有，AI 会主动发出温和劝阻：“检测到家中还有 2 颗卷心菜，建议先吃完再买哦。”
- **简易菜谱规划**：“用冰箱里现有的菜能做什么饭？” -> AI 自动检索现有食材，排除用户的忌口，推荐极简懒人菜谱。
- **全语音播报**：做家务/开车时不便看手机，触发指令“念一遍快过期的东西”，AI 全程语音播报。

### 4. 数据与配置

- **基础配置**：AI 所需的 API Key、Model、Base URL 均可在前端页面或环境变量中自由配置。
- **对话记录**：
  - 独立 AI 对话页：聊天式布局。
  - 历史记录永久留存，支持按时间/物品检索。
  - 支持一键清空历史，保护隐私。

## 🌐 Web 端设计 (Web Interface)

### 1. 首次进入页（初始化设置）

引导用户完成“松鼠建巢”的基础配置，让 AI 更聪明、更贴心：

- **生活画像配置**：
  - *饮食偏好*：是否在减肥（AI 菜谱优先推荐低卡食材）、是否有特殊忌口（如不吃海鲜、不吃牛羊肉等，AI 会在推荐时自动过滤）。
  - *家庭结构*：单身、情侣/合租、多口之家（开启多成员录入模式）。
- **空间映射（勾选/拖拽我的松鼠洞）**：
  - 冰箱（冷藏上/中/下层、冷冻层、保鲜盒）
  - 储物柜（零食箱、调味架）
  - 卫生间（镜柜、洗漱台下）
- **提醒策略**：
  - *保质期激进程度*：严格主义（到期即扔） vs 临界探索者（提示“闻闻看，没坏就能吃”）。
  - *免打扰时间*：设定每日早/晚定时播报的时间点。

### 2. 首页布局

- **AI 多模态对话窗口（支持图片识物）**：
  - *场景1（小票/合照识别）*：买菜回家，拍一张小票或将食材拍个大合照上传，AI 自动圈出 [菠菜、西红柿、酸奶] 并预估保质期，用户口头一句“都放冰箱”即可一键录入。
  - *场景2（无感消耗）*：吃完按住麦克风说“西红柿吃完了”，自动出库。
- **三色预警卡片（核心视觉中心）**：
  - 🔴 **红卡**：今日过期/已过期。
  - 🟡 **黄卡**：3 天内即刻过期。
  - ⚪ **灰卡**：长期闲置物品（如放了半年的面膜、角落的耗油）。
  - *懒人快速交互*：卡片自带「一键消灭」快捷键（已吃完/已扔掉），无需进入详情页或打字；点击「问 AI」按钮，直接获取当前临期物品的吃法/消耗建议。
- **AI 今日推荐**：
  - 根据当前“红黄灰”物资，自动生成“今日待处理清单”与“推荐消耗菜谱”。
- **物品详情页**：
  - 提供「问问 AI」悬浮按钮，随时点查当前物品的存放技巧、延伸妙用。

## 💻 CLI 端设计 (Command Line Interface)

为极客、程序员及自动化高端玩家设计的**闪电录入与管理工具**。

### 1. 核心功能

- **闪电录入**：`squirrel add "3袋螺蛳粉，放客厅箱子里"` -> 直接调用后台 AI 语义解析并入库。
- **快速查阅**：`squirrel list --status=danger` -> 终端直接打印红色预警物品列表。
- **一键清理**：`squirrel clear --expired` -> 快速清空已标记为丢弃/过期的历史占位数据。
- **数据导出**：`squirrel export --format=md` -> 强制手动导出一份精美的库存 Markdown 报告。
- **自动化集成**：可配合服务器 Cron Job，每天定时触发 Webhook 联动，向用户的微信/Telegram 发送今日库存日报。

### 2. 技术框架

- **开发语言**：使用 Go (Cobra库)。
- *注*：使用 Go 可以编译为单文件二进制工具，绿色免安装，体验极佳。

## 🐳 部署方案 (Deployment)

项目全面支持 **Docker** 与 **Docker-compose** 一键本地化部署。

### 1. docker-compose.yml 示例

```yaml
version: '3.8'

services:
  squirrel-app:
    image: squirrel/squirrel:latest
    container_name: squirrel
    ports:
      - "8080:8080"
    volumes:
      - ./data:/app/data          # SQLite 数据库与向量数据持久化
      - ./storage:/app/storage    # 存放自动生成的 inventory.md 及用户上传的图片
    environment:
      - NODE_ENV=production
      - AI_PROVIDER=openai        # 可选: openai / claud / ollama / local
      - AI_BASE_URL=https://api.openai.com/v1
      - AI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
      - AI_MODEL=gpt-4o-mini      # 推荐使用性价比高且支持多模态的模型
      - WHISPER_LOCAL=false       # 是否启用本地语音识别（若为 false 则使用线上接口）
    restart: unless-stopped
```

### 2. 部署配置说明清单

部署时，用户仅需在环境中配置以下几项：

1. **AI 供应商信息**：配置标准 OpenAI 格式的 Key 和 Base URL。若想实现**纯本地完全免费运行**，可将 Provider 设为 ollama，并在本地运行 Qwen 或 Llama3 模型。
2. **卷挂载 (Volumes)**：必须挂载 ./storage。系统自动生成的 inventory.md 将实时保存在该目录下，方便用户使用 Obsidian、Notion 或本地文本编辑器直接读取和备份。
3. **端口**：默认 Web 访问端口为 8080，可根据宿主机占用情况自行映射。
